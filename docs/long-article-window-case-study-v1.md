# 长文章语义窗口：单篇实测

## 样本

- 来源：`jazzyear-research`
- 文章 ID：`162`
- 标题：`2026企业级智能体白皮书`
- 清洗后长度：`2,571` 字符
- Gold 事件：1 条，主体为 `九科信息`，类型为 `technical_milestone`

## 判断

这篇文章属于“重大事件 + 后续扩写”，而不是采访稿或多事件周报。

前 2,000 字符内已经出现完整的事实句：

> 九科信息针对国央企及大型企业的严苛需求，推出 bit-Agent 企业级智能自动化平台，作为连接人类意图与异构系统的“元枢纽”。

2,000 字符之后主要是产品机制、行业背景和观点扩展，没有新的独立公司事件。规则路由结果：

```json
{
  "mode": "single_event_expansion",
  "reason": "concrete_lead_event_followed_by_long_form",
  "original_chars": 2571,
  "semantic_chars": 2000,
  "prefix_has_concrete_event": true,
  "prefix_action_count": 6,
  "tail_action_count": 0
}
```

## 验证结果

系统将尾部替换为空格而不是直接删除，因此原文字符偏移和引用位置不变。实体账本在只看该 2,000 字符窗口时仍识别出 `九科信息`，并生成 10 条可审计 Claim；Gold 事件对应的 Claim 能精确覆盖原始证据句。

这次样本也暴露并修复了一个独立问题：`九科信息` 是没有“科技/集团”等公司后缀的短品牌，旧规则只把它当作 discovery，导致事件无法绑定。现在只有“短名称 + 正文主语位置 + 同句具体动作”同时满足时才提升为 eligible，避免把标题片段或候选提示直接当成公司。

## 目前的边界

- `AI 周报`、融资周报等多事件汇总会路由为 `multi_event_digest`，不执行 2,000 字符硬截断，而交给现有的条目/标题边界拆分。
- 采访或评论类文章在前 2,000 字符没有具体事件时标记为 `skip_low_value`，正文保留原始长度但对语义提取器全部遮蔽。
- 这是一篇单样本通过，不代表 development-v2 整体已经通过。当前整体 Gold 覆盖仍受多事件摘要中的实体归一和产品—母公司绑定问题影响，必须在下一轮独立审计中继续处理。
