# MiniMax M3 对照实验（2026-07-26）

## 实验设计

使用同一份 10 家具身智能公司事实包、同一套 three-shot system prompt、同一修复提示、同一温度 `0.2`、同一输出上限和同一确定性证据门槛。唯一变量为模型：生产基线 `MiniMax-M2.7-highspeed` 对照 `MiniMax-M3`。M3 输出写入隔离目录和独立 SQLite，不覆盖生产人才池，也不发送飞书。

## 结果

| 指标 | M2.7-highspeed | M3 |
|---|---:|---:|
| 公司事实包 | 10 | 10 |
| 完成公司分析 | 9 | 10 |
| 结构错误 | 0 | 0 |
| 证据门槛错误 | 1 | 0 |
| 岗位假设 | 5 | 5 |
| 去重后人才主题/草稿 | 5 | 4 |
| 城市字段合规 | 5/5 | 4/4 |
| 大致运行时间 | 约 15 分钟 | 约 5 分钟 |

M3 对证据不足的“未来不远机器人”直接返回空岗位和可观察信号，没有像 M2.7 那样先生成无法通过 watchlist 证据门槛的岗位。M3 还把傲意科技与因时机器人的同类“灵巧手量产工程化总监”聚为一个跨公司人才主题，减少重复广告。

M3 的岗位标题整体更贴近事实包中的业务责任，例如：

- `具身智能物理世界模型与数据飞轮研发总监`
- `具身智能商业闭环与行业交付总监`
- `灵巧手量产工程化总监`
- `人形机器人学术研究与开发者生态合作总监`

## 决策

每日任务默认改用 `minimax/MiniMax-M3`，但仍通过 `LEAD_RADAR_LLM_MODEL` 保留显式覆盖能力，可立即回退至 `minimax/MiniMax-M2.7-highspeed`。不修改 OpenClaw 全局主模型，也不复制 API Key；Lead Radar 继续复用同一 Provider 的凭证和 base URL。

M3 官方将其定位为更强的 agentic/多步推理模型，并支持思考开关。当前任务需要“阶段变化 → 新增责任 → 组织缺口 → Director+ 岗位”的多步推理，因此本轮保留思考模式，不为进一步缩短延迟而关闭。生产产物与飞书汇总新增实际模型名，便于后续按日人工观察。

本实验只是一批固定样本，不建立系统原生结果评分器。建议连续观察至少 7 次每日运行，再由人工反馈决定是否调整提示词或回退模型。
