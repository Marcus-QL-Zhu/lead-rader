# 聚合信源专属适配器开发规范

本规范由 36 氪融资快报参考实现冻结而来，适用于第一批其余九个聚合信源。

## 1. 适配器责任边界

每个站点适配器只负责三件事：

1. 枚举入口页公开展示的全部增量文章；
2. 从公开详情页提取正文和结构化字段；
3. 生成有逐字证据支持的确定性事件种子。

公共协调器负责增量状态、原始页审计包、逐文章 MiniMax 调用与修复、SQLite
持久化、死信、健康指标和 Evidence 转换。站点模块不得自行调用 MiniMax。

## 2. 列表完整性

- 优先使用公开 RSS、XHR、JSON-LD 或页面内嵌 JSON；没有时才解析 DOM。
- 精确选择器必须覆盖验收窗口公开列表中的全部文章，不得先按关键词过滤。
- `SourceArticleIndex` 的 ID、URL、标题、时间和列表位置必须可追溯。
- URL 必须通过 host 和 path 白名单；分页终止必须有确定条件。
- 同一文章的重复展示可在索引内去重，但不得漏掉独立文章。
- 详情页失败必须进入死信；允许使用完整列表标题/摘要做明确标记的降级输入。
- 高频快讯允许在全量建索引后做宽口径确定性预过滤；每个被排除条目必须持久化为
  `prefiltered`，验收时对原始全量检查假阴性，不允许只验收进入 MiniMax 的子集。

## 3. Scrapling 自适应

每个关键列表/正文选择器都应使用 `AdaptiveSelector.css`：

1. 精确 CSS；
2. `auto_save=True` 保存已验证元素特征；
3. 精确 CSS 失效后以最低 72% 相似度自适应定位；
4. 自适应结果仍须通过数量、URL、标题、日期、正文长度和标题对应关系校验；
5. 不变量失败时 fail closed。

Scrapling 只用于 DOM 漂移恢复。禁止使用 stealth、代理轮换、验证码处理或
其他访问控制绕过能力。

## 4. 事件口径

`SemanticEvent` 的融资字段口径如下：

- `event_status=completed`：融资已经完成；
- `event_status=started`：公开启动、开启或提前开始融资；
- `funding_amount`：仅表示当前事件金额；
- `cumulative_funding_amount`：多轮或累计口径；
- 历史背景（例如“该轮之前曾于三月完成种子轮”）不作为文章发布日的增量事件；
- 一篇汇总文章中的不同公司、不同轮次必须分别生成事件；
- 未具名描述（例如“知名产业方”“某大厂早期投资人”）不得进入 `investors`。

非融资站点仍使用同一数据契约，按公开事实选择 `event_type` 和 `phase`。
不得从行业常识推导未在原文出现的主体、金额、日期、投资人或事件。

## 5. MiniMax 融合

- 站点规则是完整性下限，不因 MiniMax 少输出而被删除；
- MiniMax 只做主体别名、事件语义、投资方和行业标签消歧；
- 每个事实必须出现在所引用的 `evidence_quotes` 中；
- 相同主体的品牌名和法律实体名按规则种子归一；
- 一次修复后仍不合格时保留规则种子、记录完整审计并写入可重试死信；成功重试关闭死信；
- 规则种子和 MiniMax 事件合并后，同篇文章不得存在同一语义事件重复。

## 6. 最低测试集

每个适配器至少提供：

1. 固定列表 fixture：全部条目 100% 建索引；
2. 固定详情 fixture：正文不含导航、相关推荐或页脚；
3. 至少一个明确正例和一个容易误判的负例；
4. 多事件文章测试（若该站点存在日报/快讯汇总）；
5. 精确选择器失效后 Scrapling 自适应恢复测试；
6. 第二次运行不重复抓取未变化详情页的测试；
7. 运行时审计包：原始列表、原始详情、清洗正文、规则事件、MiniMax
   首答/修复答、最终事件。

## 7. 独立验收

实现者不能批准自己的适配器。独立验收代理必须逐条对比原始网页和最终语义：

- 公开增量文章无静默遗漏；
- 当前增量主体和事件无遗漏；
- 主体事实错误为 0；
- 事件状态事实错误为 0；
- 金额、轮次、投资方事实错误为 0；
- 历史背景不冒充当日增量；
- 同篇语义事件不重复；
- 所有不可访问条目有失败记录。

只有上述条件全部满足才可标记为 PASS。
