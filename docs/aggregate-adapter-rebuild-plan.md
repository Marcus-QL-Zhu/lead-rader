# 聚合信源专属适配器重建计划

状态：已完成（代码、独立验收与生产部署）
负责人：Codex 主会话
目标版本：Lead Rader 聚合信源采集架构 v2

## 1. 目标

将当前“通用 HTML 链接解析器 + 标题关键词过滤”升级为：

1. 每个高价值聚合信源拥有专属增量发现与正文解析器；
2. 每个公开可访问的当日增量条目都进入可审计索引，不在列表标题阶段静默丢失；
3. 精确选择器失败时，使用 Scrapling 保存的元素特征进行受控自适应定位；
4. 先做正文清洗和确定性规则，再对语义歧义使用 MiniMax；
5. MiniMax 输出必须引用输入事实，经过 严格字段结构 与确定性校验；
6. 公司实体归一后再执行跨来源事件聚簇；
7. OpenClaw 读取聚簇后的快照、Top 候选简表和采集健康指标；
8. 每个适配器必须经实现者之外的子代理独立验收。

Scrapling 只解决 DOM 定位漂移。它不负责事实判断，不用于绕过登录、
验证码、robots.txt、网站条款或其他访问控制。

## 4. 每日增量算法

1. 读取上次成功游标；
2. 从最新列表页开始分页；
3. 保存列表中每个公开条目的索引；
4. 遇到已知稳定文章 ID 后继续扫描 48 小时重叠窗口；
5. 达到重叠窗口末端后停止；
6. 使用 `source_id + source_article_id` 和 canonical URL 去重；
7. 对新条目逐个抓取详情；
8. 失败条目进入重试/死信队列，不得静默删除；
9. 次日运行重新核对上一自然日文章数；
10. 记录列表总数、增量数、正文成功数、规则结果数、MiniMax 数和异常数。

财联社和证券时报属于高频快讯流：仍然对列表中的每一条公开增量建立索引，
再用覆盖机械、电气、软件、算法、芯片、航天、能源、材料和生物医药的宽口径
确定性路由决定是否抓取详情。被路由排除的条目以 `prefiltered` 状态保存，
不得静默删除；独立验收必须对原始全量检查路由假阴性。

## 5. 解析与 Scrapling 策略

每个字段按以下顺序解析：

1. 公开 RSS、XHR、页面内嵌 JSON 或 JSON-LD；
2. 站点专属精确 CSS/XPath；
3. Scrapling `auto_save` 保存已验证元素；
4. 精确选择器失效后启用 `adaptive=True`；
5. 自适应结果必须通过字段不变量：
   - URL 域名和文章路径符合白名单；
   - 标题非空且不是导航项；
   - 日期可解析且不在未来；
   - 正文达到最小长度且正文/标题相似；
   - 列表条目数量不发生不可解释的突变；
6. 不变量失败时 fail closed，并进入告警。

不使用 Scrapling 的 stealth、代理轮换、验证码解决或访问控制绕过能力。

## 6. 规则与 MiniMax 分工

### 确定性规则

- 依据专属频道设置事件先验；
- 标题中明确的融资、投产、中标、高管任命等事件优先于正文页脚噪声；
- 从结构化区域提取日期、金额、轮次、投资人；
- 清除导航、推荐、广告、页脚和招聘入口；
- 识别法律实体名称，拦截项目名、产品名、新闻标题和政策标题。

### MiniMax

- 只接收清洗正文、规则结果和有限证据片段；
- 按文章处理语义歧义或需要行业/组织责任解释的内容；
- 按 `content_hash + prompt_version + model` 缓存；
- 输出必须通过严格字段结构、枚举值和逐字证据校验；
- 每个主体、金额、轮次和投资方必须能在输入的逐字证据中定位；
- 一次修复后仍失败则保留确定性规则结果，并进入可重试死信队列；后续成功重试会关闭对应死信；
- 不允许模型覆盖确定性来源、URL、日期和文章 ID。

## 7. 聚簇和下游

实体归一键：

- 法律实体名；
- 品牌别名；
- 英文名；
- 公开组织标识；
- 人工确认的正/负实体边。

事件聚簇键：

- canonical company；
- canonical event type；
- 事件日期窗口；
- 融资轮次/金额、项目名、投资方等识别槽位；
- 独立来源域名。

聚簇后保留所有来源 URL，不重复计分。OpenClaw 只读取聚簇后的快照，
但可以按命令展开原始文章和语义处理记录。

## 8. 验收协议

每个适配器选择至少一个已经结束的公开自然日作为封闭验收窗口。

### 增量完整性

- 独立子代理枚举原始列表全部公开条目；
- 与适配器增量索引逐条对比；
- 文章 ID、标题、URL、发布时间准确率必须为 100%；
- 可访问条目召回率必须为 100%；
- 不可访问条目必须有明确失败记录，不计为静默遗漏。

### 主体与事件准确性

独立子代理同时读取：

- 原始列表页；
- 原始文章页；
- 清洗正文；
- 规则结果；
- MiniMax 结果；
- 最终聚簇事件。

通过条件：

- 主体事实错误为 0；
- 事件事实错误为 0；
- 无原文依据的日期、金额、轮次、投资人为 0；
- 项目名、产品名、标题误判为公司为 0；
- 歧义必须标记 `unknown`，不能猜测；
- 每条事实能追溯到原始网页。

验收包属于运行时审计产物，不把完整版权正文提交到 GitHub。仓库只保存
最小化、脱敏的 DOM fixture、哈希、期望结构和验收摘要。
